## Scope

## Findings addressed

- Generic user saves could overwrite the thumbnail privacy preference with an old or omitted value. Full-user updates now preserve the stored preference; HTTP preference/user writes serialize their read-and-update step. Dedicated preference changes remain owner-scoped.
- File replacement preserving byte length and modification time could reuse an older public thumbnail. Public cache identity now includes a streamed content fingerprint, including the stream actually decoded on a cache miss. Responses use `private, no-store` and omit modification-time-only HTTP validation.
- Anonymous thumbnail processing needed independent resource bounds. Source reads are streamed and cancellation-aware, capped at 64 MiB; public full-decode preflight caps images at 25 million pixels and header inspection at 1 MiB. Two public jobs run at a time with a 30-second request context. Rejected images fall back to the existing file icon, never raw content.
- Late gallery directory responses could overwrite newer navigation or update a closed viewer. Requests now abort on replacement/close, apply only to their captured route/generation, and discard cached listings when the parent folder changes.
- Image/video toolbar behavior depended on route timing rather than the resource's actual media type. Controls now respond to metadata transitions; hidden state persists between images. Query strings no longer become part of the preview filename.
- Release publishing did not depend on frontend tests. The release job now requires `test-frontend` as well as lint, backend tests, and build.

## Reviewed invariants

- Gallery zoom/pan bounds, single vs. double tap, pinch release, swipe cancellation, rotation, source replacement, native image loading, TIFF/RAW fallback, stale responses, timers, observers, and event-listener cleanup.
- Video slides retain their existing media sequence and video-specific keyboard behavior. Desktop image context menus remain available.
- Public thumbnails revalidate share password/token, expiry, owner permissions, scope/rules, upload-only policy and preference before internal cache reads. They re-encode supported images to JPEG without raw-file fallback or embedded EXIF-thumbnail reuse.
- Share selection reuses the existing icon component, includes entries beyond the render limit, and rejects upload-only selection. It adds no server permissions or write operations.
- Folder shares keep their existing visible-entry count under the requested **Files** label. Single-file shares retain human-readable byte size. The canceled public folder-size endpoint and all automatic recursive size work were removed.
